Hosting RangerTrak yourself

For people who run a web server or an offline hub and want to serve RangerTrak to phones and tablets nearby, such as a club's field kit, a radio software collection or a community emergency hub.

RangerTrak is a web app that runs entirely in the browser. There is no database and no server code: the release zip is a folder of static files, and any web server can serve it. Each device keeps its own data on the device.

Don't run a web server? You don't need to. Use RangerTrak at rangertrak.org; it installs on the device and then works with no Internet. To share a mission from a laptop to nearby devices over local Wi-Fi, use the Board, which ships with RangerTrak's source (Start Command Post Server; it needs Node.js 24 or newer). A ready-to-run Board download is planned.

What's in the zip

  • READ-ME-FIRST.html: this page.
  • LICENSE: the GNU Affero General Public License, version 3.
  • rangertrak/: the app. Serve this folder's contents as the web root.

The offline basemap and the demo maps are not in the zip. See Maps below.

The four rules

1. Serve it over HTTPS

Browsers only allow three things RangerTrak depends on over HTTPS (or on localhost):

  • the offline install (service worker), which keeps the app working with no network;
  • encryption, for encrypted backups and on-device encryption;
  • location, for position fixes from the device's GPS.

Over plain http:// from an IP address, the app opens, but none of those three work.

A self-signed or private certificate is fine, but each device must trust it. If you only click past the certificate warning, browsers still refuse to install the offline copy. Install your certificate (or your private certificate authority) on each device, or use a real certificate for a name you own.

2. Give it its own hostname, at the root

Serve it at https://rangertrak.your-hub.example/, not under a path like https://your-hub.example/rangertrak/. The app is built for <base href="/"> and its offline install covers the whole site.

3. Send app pages back to index.html, but let missing files be 404

Addresses like /map or /radio-log are pages inside the app, not files. The server must answer any path that isn't a file with index.html.

The exception is /assets/: a file missing there must return 404, not index.html. The map files are deliberately missing, and a web page sent in their place can be cached by the app as if it were a map.

4. Support range requests

The map files (.pmtiles) are read a piece at a time with HTTP range requests. Most servers support this by default for static files; some proxies and caches don't.

Example configurations

Caddy

Caddy can make and renew a local certificate itself (tls internal). The devices still have to trust Caddy's local certificate authority (rule 1).

rangertrak.your-hub.example {
    tls internal
    root * /srv/rangertrak
    encode gzip

    handle /assets/* {
        file_server
    }
    handle {
        try_files {path} /index.html
        file_server
    }
}

nginx

server {
    listen 443 ssl;
    server_name rangertrak.your-hub.example;
    ssl_certificate     /etc/ssl/rangertrak/cert.pem;
    ssl_certificate_key /etc/ssl/rangertrak/key.pem;

    root /srv/rangertrak;

    location /assets/ {
        try_files $uri =404;
    }
    location / {
        try_files $uri $uri/ /index.html;
    }
    types {
        application/manifest+json webmanifest;
    }
}

The rangertrak/_headers file lists the security and caching headers rangertrak.org sends. It uses Cloudflare's format; copy whichever ones your server supports. If you copy none, the app still works.

Maps

RangerTrak has two maps.

  • The standard map loads its tiles from the Internet. With no Internet, it shows only the areas a device saved beforehand.
  • The Alternative map reads map files from the device. The zip has no map files, so it is blank until you add one for your area. Cut a file for your area with the free pmtiles tool, then load it on each device under Map → Alternative map → Load a custom .pmtiles file…. The Field Guide has the steps (search it for “make your own offline map file”).

Because the world basemap is missing, the app's offline-readiness check will report that the Alternative map isn't ready for offline use. That's expected for a zip install.

The demo missions still load, but without their street-level maps.

What else to expect

  • Data belongs to the address it was opened from. A tablet that opens RangerTrak from your hub keeps that data separate from the same tablet's rangertrak.org copy. Nothing moves between them on its own; to move a mission, export a backup in one and import it in the other.
  • Anything that needs the Internet needs the Internet. Online map tiles and address lookup don't work on an offline hub. The feedback button falls back to a link to GitHub.
  • Updates. To update, replace the folder with the one from a newer release. Devices pick up the new version the next time they open the app while they can reach your server.
  • Privacy. The roster and the radio log are stored on each device, not on your server. Your server only hands out the app's files.
