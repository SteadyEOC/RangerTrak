Where your data is

See RangerTrak's privacy policy for the full picture. The short version is below.

In this browser, on this device. Not on a server, not in an account, not shared with the other devices your team is using. Each browser on each device keeps its own separate copy.

That is what lets RangerTrak work with no connection. It also means the device is the only copy, so back it up.

rangertrak.org counts page loads with Cloudflare's cookie-free analytics — no cookies, and nothing you type. Your mission stays on this device. When online, the app fetches map images and looks up addresses for report locations — that happens automatically, not only when you choose to look one up. Sending feedback, and turning on Command Post Server publishing, are the two things that only happen if you choose to.

The roster is confidential

The roster holds legal names, personal phone numbers, and call signs that tie each row to a publicly searchable license record. It is stored unencrypted on the device, unless you turn on device encryption on the Mission page (Data safety > Device encryption) - which also covers field reports and ranger photos, and needs a passphrase that cannot be recovered if lost. Rangers' own Export roster, and every spreadsheet export, are plain-text files regardless. Back up mission on the Mission page is the one exception among exports: it includes the roster, and it offers an optional passphrase - leave it blank and it's the same plain file as before, type one and the file is encrypted. Share exports only with people who need them for this mission, and delete them when the mission is over.

Given a callsign, the FCC's own public licensee lookup already shows more than this roster does - legal name and mailing address for any licensed amateur radio operator. This app does not meaningfully add to that public exposure, with one exception: photographs, which are not part of any public record.

Getting data off the device

Back up mission on the Mission page is the one to reach for by default — it round-trips everything (settings, roster and reports) back in on another device, so it doubles as the actual backup. Export roster on the Rangers page moves just the roster, the same round-trip way. The Setup files page is different from both: it packages any combination of roster, photos, locations and settings — but never field reports — for setting up a NEW device before a mission starts, merging into whatever is already there rather than replacing it, which none of the others do (Export roster never includes photos or merges; Back up mission is a mid/post-mission backup that assumes reports already exist and always replaces wholesale). Export on Radio Log or Rangers instead produces an Excel-friendly spreadsheet — useful for working with the data, but one-way: it cannot be imported back in.

Ranger photographs stay on the device they were added to. They are never uploaded. Name each file after the ranger's id or callsign - any common image format works.

Make a map file for your area

The Alternative map on the Map page shows the whole world in low detail. For street-level detail where you work, make a map file for your area once, while you have a good connection, and load it onto each device.

  1. Get the free pmtiles tool from its release page (pick the file for your computer).
  2. On the Map page, turn on Use MapLibre + PMTiles Map and move the map so it shows your area. Open Get a map file for this area and press Copy command.
  3. Paste the command into a terminal (Command Prompt on Windows) and replace YYYYMMDD with a recent date from maps.protomaps.com/builds. Run it. It saves my-area.pmtiles, usually a few megabytes for a town.
  4. Back on the Map page, press Load a custom .pmtiles file… and pick that file. Do this on every device that needs the map.

Reporting a problem

The Log page records what the app did this session. On the Feedback tab, press Copy log to clipboard and paste it into the message field — it is far more useful than a description of what went wrong.

The log is cleared when you reload, so copy or export it before reloading. It is a raw diagnostic record and can contain report details, addresses and call signs, so treat it as confidential.

There is a feedback form on the Feedback tab. Anything sent through it becomes a public issue on the project's repository, so keep mission data out of it.
