Where your data is

See RangerTrak's privacy policy for the full picture. The short version is below.

In this browser, on this device. Not on a server, not in an account, not shared with the other devices your team is using. Each browser on each device keeps its own separate copy.

That is what lets RangerTrak work with no connection. It also means the device is the only copy, so back it up.

Handing a mission to another scribe

When another scribe, or the next shift, already has entries of their own on their device, use Hand over to another scribe on the Radio Log page. Hand over saves one file with the people, the places and every radio log entry. On the other device, Merge in shows what the file would add or change before anything happens, then merges it. Nothing there is replaced or removed, and merging the same file twice changes nothing.

The file holds people's names and phone numbers. Type a passphrase to lock it; leave the box blank and it is not locked. A forgotten passphrase cannot be recovered. For a blank device, use Restore on the Mission page instead.

Trying it out with a demo? If both devices loaded the same demo, they share the people and places, but each device's demo entries are new to the other, so the merge adds them all and the log looks like doubled traffic. That is expected: hand over from a device with a demo to one without, or start the second device blank.

Restored the wrong file? Undo last import

Before Restore, a Report Packet import, a Setup file or a roster import (Rangers > Import a list), RangerTrak keeps a safety copy of everything on this device for 24 hours. Until then, Mission > Data safety shows Undo last import, which puts the mission back exactly as it was just before. After a roster import it puts back only the roster and ranger photos, so nothing you logged since is lost; the same button shows on the Rangers page.

It also works after a merge, and puts back the whole mission, so anything logged since goes too (Undo says how many entries, and offers a backup first). Discard safety copy throws it away early. There is only one: the next import replaces it. The copy holds the whole roster and is locked with the rest if device encryption is on. While it exists, the photos it refers to are kept; that space comes back when it expires or is discarded.

Restore also shows a preview first: what is on this device and what is in the file, side by side, including how many entries here are not in the file and will be replaced. Cancel is the default.

Photos, video and audio on entries

Attach on the Entry page, or Add in the viewer of a saved entry, keeps a file with the entry. The original is stored exactly as it arrived, with a fingerprint (SHA-256) so a later copy can be shown to be unaltered. The viewer shows the fingerprint in short form, with a copy button.

@if (view.isShown('attachments')) { Attach is under the Notes box on the Entry page, in any browser. } @else { Attach is in Full view (the Full view button at the top of the page), in any browser. Once the mission has an attachment it shows in Simple view too. }

  • Originals keep their hidden details, including the GPS position a phone wrote into a photo. The thumbnails shown in lists and printouts do not. Think before sharing an original outside the team.
  • An iPhone may convert a HEIC photo to JPEG before RangerTrak sees it. What RangerTrak fingerprints is what it was given.
  • Files take space on this device. Mission > Data safety shows how much of the mission's attachment budget is used and lets you change it. RangerTrak warns at 80% and 100%, and asks before a file over 100 MB, but only the browser's own limit can stop you.
  • Back up mission saves an attachments file next to the backup (locked with the same passphrase). Restore accepts the backup, the attachments file or both, and refuses any file that does not match its fingerprint. A hand-over carries the attachments too.

One copy per browser

  • Each browser keeps its own copy, and the copies never sync. Chrome and Edge on the same laptop are two separate RangerTraks.
  • Only one tab or window at a time. If RangerTrak is open elsewhere in the same browser, a second tab says RangerTrak is already open and does not save.
  • On iPhone and iPad, RangerTrak added to the Home Screen is a separate copy from the one in Safari (see Getting started).
  • To run two missions at once, use two browsers, or two profiles in one browser. Give the missions different names, so a Report Packet opened in the wrong one is flagged. Only one of them should publish to a given RangerTrak Board, which shows whichever log reached it last.
  • Never use a private or incognito window. Everything in it is erased when it closes.

When online, the app fetches map images and looks up addresses for report locations — that happens automatically, not only when you choose to look one up. Sending feedback, and turning on RangerTrak Board publishing, are the two things that only happen if you choose to.

The roster is confidential

The roster holds legal names, personal phone numbers, and call signs that tie each row to a publicly searchable license record. It is stored unencrypted on the device, unless you turn on device encryption on the Mission page (Data safety > Device encryption) - which also covers radio log entries, after-action notes, ranger photos and attachments, and needs a passphrase that cannot be recovered if lost. Rangers' own Export roster and Export changes, and every spreadsheet export, are plain-text files regardless. Back up mission on the Mission page is the one exception among exports: it includes the roster, and it offers an optional passphrase - leave it blank and it's the same plain file as before, type one and the file is encrypted. Share exports only with people who need them for this mission, and delete them when the mission is over.

Given a callsign, the FCC's own public licensee lookup already shows more than this roster does - legal name and mailing address for any licensed amateur radio operator. This app does not meaningfully add to that public exposure, with one exception: photographs, which are not part of any public record.

Getting data off the device

Back up mission on the Mission page is the one to reach for by default — it round-trips everything (settings, roster and reports) back in on another device, so it doubles as the actual backup. It includes ranger photos, and your Google geocoding key only if you protect the backup with a passphrase. Export roster on the Rangers page moves just the roster, as a spreadsheet that Import a list reads straight back in.

Export changes, beside it, is for after an event: it saves only the rangers added or edited on this device since the roster was imported, so whoever keeps the master list can add the walk-ups and fixes without combing through the whole roster. The Setup file card on the Mission page (under Data safety) is different from both: it packages any combination of roster, photos, places and settings — but never radio log entries — for setting up a NEW device before a mission starts, merging into whatever is already there rather than replacing it (Export roster never includes photos; Back up mission is a mid/post-mission backup that assumes reports already exist and always replaces wholesale). Print roster on Rangers and Print places on the Map page print the same lists on paper, grouped by team and by category (the roster sheet carries names and phone numbers, so keep it safe). Export on Radio Log produces an Excel-friendly spreadsheet — useful for working with the data, but one-way: it cannot be imported back in.

Ranger photographs stay on the device they were added to. They are never uploaded. Name each file after the ranger's id or callsign - any common image format works.

Make a map file for your area

The Alternative map on the Map page shows the whole world in low detail. For street-level detail where you work, make a map file for your area once, while you have a good connection, and load it onto each device.

  1. Get the free pmtiles tool from its release page (pick the file for your computer).
  2. On the Map page, turn on Use MapLibre + PMTiles Map and move the map so it shows your area. Open Get a map file for this area and press Copy command.
  3. Paste the command into a terminal (Command Prompt on Windows) and replace YYYYMMDD with a recent date from maps.protomaps.com/builds. Run it. It saves my-area.pmtiles, usually a few megabytes for a town.
  4. Back on the Map page, press Load a custom .pmtiles file… and pick that file. Do this on every device that needs the map.

Reporting a problem

The @if (view.isShown('debug-log')) { Log } @else { Log } page records what the app did this session. On the Contact us tab, press Copy log to clipboard and paste it into the message field — it is far more useful than a description of what went wrong.

The log is cleared when you reload, so copy or export it before reloading. It is a raw diagnostic record and can contain report details, addresses and call signs, so treat it as confidential.

There is a feedback form on the Contact us tab. Anything sent through it becomes a public issue on the project's repository, so keep mission data out of it - or email the maintainer privately instead, from the same tab.
